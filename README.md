# 絵QR (e-qr)

**https://e-qr.vercel.app**

QRコードの誤り訂正の余裕ぶんだけ絵を描き込めるエディタ。Reed–Solomon の「壊していい量」をブロックごとに数えながら塗り、読めなくなる手前で筆が止まります。毎ストローク jsQR に実際に読ませ、読めないときは書き出しボタンが押せません。
すべてブラウザの中で動きます。

## つかう

```
pnpm install
pnpm dev     → http://localhost:5870
pnpm test
```

## 作りの要点

- **数えるのはモジュールではなく符号語。** QRのデータは8ビットの符号語に区切られ、ブロックごとに RS 符号で守られている。1ブロックで直せる誤りは `t = ⌊(EC符号語数 − p)/2⌋`(p は1〜3版で誤訂正よけに取っておく予備)。同じ符号語の中なら何ビット壊しても1つと数えるので、「既に壊した符号語の中はタダ」になる。
- **色は明暗だけが効く。** jsQR と同じ重みの輝度で暗(≤90)/明(≥165)に分け、元のモジュールと同じ明暗の色ならどれだけ塗っても予算を使わない。間の明るさは2値化のしきい値しだいでどちらにも転ぶので、常に「壊した」と数える。
- **配置表は自前、照合は実物で。** モジュール→(ブロック, 符号語, ビット)の対応はジグザグ配置とインタリーブから自前で作り、qrcode-generator が出した実物を読み戻して全ブロックのシンドロームが0になることをテストで確かめている(24通りの版×レベル、最大で20版台まで)。
- **安全マージン = t の半分。** 実カメラのボケ・にじみ・照明ムラが足してくる誤りのため、各ブロック t の半分で止める。テストで「t ちょうどまで壊すと jsQR はきれいな画像なら読める」「t+1 で読めなくなる」「t ちょうどの絵は強いボケ(blur 2)で20回中ほぼ全滅、半分で止めた絵は19回以上読める」を固定している。
- **検査は2段。** 書き出す PNG そのもの(1モジュール16px)と、1モジュール4pxに縮めてノイズ→ぼかし→コントラスト低下→照明の傾きを足した画像(乱数の種3つ)。両方読めたときだけ書き出せる。劣化画像の検査は、何も描いていない QR なら1〜15版すべて通ることをテストで確かめている(検査そのものが不公平でない)。
- ファインダ・タイミング・位置合わせ・形式情報・型番情報は訂正の外なので明暗を変えられない(同じ明暗の色は塗れる)。余りビットは復号器が読まないので何で塗ってもよい。
- 15版まで。それより大きいとモジュールが細かすぎて絵の道具にならない。

## 保証しないこと

実際のスマホで読めるかは端末・アプリ・印刷・距離しだい。jsQR は復号器の1つにすぎないので、書き出したら手元の端末で確かめてから使ってください。

## 構成

- `src/lib/` — 純粋関数(GF(256)・RSブロック表・配置表・形式情報・色の明暗・予算の会計・劣化シミュレーション・jsQR検査)
- `src/main.js` — 配線と描画。`window.__app` から状態の確認・一括塗り・お手本・書き出し可否を叩ける
- `test/` — Vitest
